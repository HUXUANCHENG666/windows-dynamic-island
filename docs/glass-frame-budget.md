# t54/t55/t56：薄边、连续圆角、帧预算

目标是 60fps / 16.67ms；**不是已经实测稳定 60fps**。

## 可证实的几何根因

- 旧 `RimBand = max(8, shortSide * .26)`：534×230 卡片带宽 59.8 DIP。t54先改为6 DIP；t56按反馈适度增至 `min(9 DIP, shortSide * .20)`，DPI 换算后物理厚度乘 DPI，用户大小/展开不再把带宽成比例放大。外框 1.5 DIP 高光描边是另一回事，保留。
- 旧内角独立 clamp：同一张 r=35 卡片，内缩59.8，却将内角保留到19.25；内角中心变成79.05，而外角中心为35。新内沿由外 SDF 的 `d=-band` 定义，半径 `max(0,r-band)`，不再另外夹到12或0.55r。
- t55 的另一真因：WPF 实际 clip 用展开 n≈4.5 的 squircle，CPU/HLSL 却算正圆圆角。相同 r 并非相同曲线。玻璃模式现用 `GlassGeometry` 和精确 `RectangleGeometry`，外框/命中、GlassHost/内容 clip 同源；近黑模式继续原 squircle。描边中心线向内移0.75 DIP、半径减0.75，避免外边界中心描边被裁半。
- 旧 GlassShade/折射/GPU 整层随速度分别平移最高15.4/11/12.1 DIP，而外框 clip 不动，层间圆角必然错位。现在这些几何图层不单独平移；流体仍在取样法线/深度里实时演算。全部图层共同继承 PillHost 的 Q 弹/非均匀缩放，捕获排除域使用同一形状的逆变换；实际取色坐标也应用同一个缩放和原点（不能只改mask）。捕获矩形跟随缩放后实际外接框，避免高DPI/Q弹时外边超出旧pad。

## 不是用模糊掩盖接缝

旧采样从每点沿圆角法线延伸到**矩形**外，距离随角度变化，再投影到四带，不能作为圆弧的连续平行曲面。只抓四带也丢失“外圆弧之外、矩形以内”的真实桌面。分段 pad 尺寸拉伸会再次改变纹理尺度。

现在以解析 SDF 法线 `n` 和有符号距离 `d` 计算最近外表面 `p-d*n`；沿同一法线外推约4～7.5 DIP，加上有界的流体扰动。圆角到直边共用这一个公式，无矩形选带/对角分支。捕获用一次完整局部 BitBlt，随后仅清除真正的当前圆角岛（含1 DIP保护边），圆角外像素保留。每像素五个局部双线性 tap、RGB共用坐标，不拆通道。

缓存按屏幕坐标平移，不再把岛洞分段拉伸。旧捕获中被自身遮挡或尚未捕获的地方，不强行投射到别的边“猜”颜色；按有效覆盖率淡出，等待新捕获。这避免展开/回缩时从未知区域制造斜楔。最多仍可能有捕获/异步渲染延迟，不承诺每个显示刷新都拿到同一时刻桌面。

## 16.67ms预算逐段优化

| 阶段 | 原先问题 | 当前机制 / 仍有限制 |
|---|---|---|
| 调度 | 移动捕获50ms最多20Hz；玻璃停稳可能退80ms慢循环 | 玻璃可见持续走CompositionTarget.Rendering；捕获目标1/60秒，0.75ms时钟容差；不是固定写个60的FPS承诺 |
| 捕获 | 每次建销DC/DIB、四次BitBlt，完后等UI回调 | DC/DIB按64像素桶只增不缩复用，一次BitBlt保留圆角外桌面；捕获仍单任务，慢于预算时实际捕获率会下降 |
| 数据交接 | 每帧clone整个pad与多个流体数组 | pad引用计数+ArrayPool，渲染期间不会重写；小流体高度快照复用；缓存没变不重传GPU |
| CPU回退 | 宽带、双pass、有限差分多次SDF、每帧新冻结位图 | 解析法线、最多9DIP薄带、跳过透明中心、单pass合成；实际算法抽出到Core，无每像素/每帧分配（预分配调用） |
| GPU | 当前帧Copy后立刻Map(Read,None)同步等待；角度带宽耗材 | 三槽staging，最多三个DO_NOT_WAIT探测，取最新已完成帧，旧帧丢弃；没完成就跳过而非设备失败；只拷实际viewport区域；可复用桶纹理；五次硬件双线性（非20次手动Load），透明中心在流体采样前剔除；运行时HLSL也用O3 |
| UI | 每完成帧新建/冻结WPF位图，重建纹理 | 稳定尺寸复用一个WriteableBitmap，只WritePixels一次；CPU与GPU共享提交；UI上传仍是一次内存复制，仍可能成为瓶颈，并非零拷贝D3D共享表面 |
| 呈现 | Rendering回调计数被误当作新折射帧率 | 单独记录新完成帧和UI新帧提交；没有DWM/显示器实际present计数，明确标unknown |

捕获任务一个、渲染CPU任务一个、完成槽一个，GPU在飞最多三个槽；忙时不排无限任务。GPU优先仍只选硬件，不筛显卡名；初始化/设备故障自动CPU回退，约10秒再试。验证用WARP入口仅验证工程编译，正式应用没有WARP入口。

## 本地诊断：无屏幕内容，无联网

每约10秒日志一条 `glass ...`：

- `completed/s`：真正完成的新折射像素帧；`path gpu=... cpu=...` 为该段完成数。
- `ui-submit/s`：WritePixels后交给WPF的新帧，不是显示器FPS。
- `capture/s` 和 `capture-fail`：成功捕获与失败次数。
- `p95-ms capture`：BitBlt、mask与复制的后台总耗时；`render-worker` 包含CPU计算或GPU提交/非阻塞轮询的CPU墙钟时间。
- `gpu-submit-poll` 不等于GPU硬件执行时间；`ui-write` 仅UI复制时间；`frame-age` 从渲染请求到UI提交（含后台/读回/调度延迟）。p95使用最近最多256个样本，不保存无限队列。
- `render-busy`、`gpu-busy` 是跳过请求，`replaced`、`discarded` 是完成槽覆盖或GPU旧槽/尺寸更换的丢弃；`presented-fps=unknown`。

不记录像素、文字、屏幕截图、窗口标题或识别到的内容。遇到慢机器先看capture/s、completed/s、ui-submit/s和frame-age，不能拿单个Rendering回调的“motion fps”当玻璃60fps。

## 自动化与合成测量边界

- Core **261测试**（t56含设置策略及9DIP限幅）：保留黑|黄、红|蓝、灰阶与抗RGB串色；新增八个切线接点/45°附近实际取样坐标的差分上界、网格/斜线/文字式条纹/双色图案沿整弧到直边的真实过滤像素连续性、DPI 1/1.25/1.5/2及用户大小0.85～1.4、101帧内外角/描边中心/逆变换捕获域一致性、完整CPU预乘色与透明中心、热循环零分配。
- `dotnet run --project tools/GlassProbe -c Release -- <临时输出目录>`：实际Core CPU回退在534×230、r35、带流体高度场、180次调用，box Linux一次结果t56的9DIP版本平均约2.898ms、p95约4.877ms、测量循环分配0字节。它预分配输出与输入，**不含捕获、池租还、任务调度、快照、UI上传、GPU或显示器呈现，不是Windows/GPU FPS**。该工具只生成合成PPM，不读取屏幕。
- Windows CI：继续 `fxc /WX /Ges /O3` 编译实际内嵌VS/PS 5.0和4.0；额外用无窗口D3D11 **WARP软件设备**运行实际shader与三槽非阻塞读回，12个DPI/背景/流体组合对照实际CPU像素，阈值4/255。WARP测试结果以CI日志为准；不是RTX3080或Intel硬件实测，也不是WPF窗口预览。
- WPF Release交叉构建要求零警告；真实Windows窗口、DWM/分层窗口兼容性、显示器刷新、UI上传耗时、eGPU/热拔插、跨屏捕获仍待用户真机验证。异步画面存在帧龄，快速展开时最外层clip和描边总是当前几何，纹理可能仍来自最近已完成的旧帧；不宣称消除了所有视觉延迟。

## t61 实况位移场

边缘几何、9 DIP 限幅和捕获/渲染任务上限不变。内部改用有阻尼的位移/应变场当场扭曲这一帧的实况垫边，不再合成历史捕获。静止后内部重新变回真透明。细节、合成图和未验证项见 [液态光学](glass-liquid-optics.md)。内部扭曲在 CPU 回退上会多走中心附近的判定，但落到岛洞的采样不再填色；GPU 同样有内部分支。不要把合成探针或 WARP 对照说成已稳定 60fps。
