# t61：用惯性位移场干扰此刻的实况画面

内部仍然通透，不铺模糊或近黑遮罩，也不把旧捕获/历史垫边像素贴回岛里。滞留感来自有阻尼的位移与应变场：渲染始终采样**这一帧**的实况捕获，把采样坐标当场扭曲、折射；场收敛后不再覆盖，动态桌面从真透明中心继续更新。

## 用户否定的做法

t59 把历次有效垫边按世界坐标合成进 `LiquidBackdrop` 图集，再按滞后坐标去取「曾经露在外面的旧像素」。这是在用历史截图像素充当液体滞留，不是对此刻透过画面的算法干扰。本轮已删除该图集和捕获合并路径。

## 根因与平台限制

此前只有最多 9 DIP 的边缘从岛外垫边取色；内部直接写 0，分层窗中间是真透明，拖动时透过的是 1:1 实景。已有浅水高度场只扰动边缘采样。

在排除本窗的捕获尚不可用或被判定为黑块/空洞时，仍会挖掉岛身，算法只扭曲当前垫边；一旦判定为正下方实况，内部位移场也会采样这些像素。详见 [正下方捕获](glass-underlay-capture.md)。

## 做法

- `LiquidOptics`：对岛的屏幕位置和尺寸做近临界弹簧（k=81，c=17，ζ≈0.94）。窗口仍 1:1 跟手，Q 弹不变。位移上限 48 DIP，尺寸滞后上限 56 DIP，跨屏或超过 240 DIP 的跳跃直接对齐。静止约 0.4 秒内收敛；偏移低于约 0.75px 时强度为 0，避免微抖。
- 内部采样是对**当前帧**的 UV 扭曲，而不是查找旧图：`sx = x - lagX + (x-cx)·(1/lagScaleX - 1) + 斜率项`（RGB 同位）。平移惯性把此刻垫边弯到拖尾一侧；尺寸惯性是相对中心的径向应变，把此刻垫边弯进正在变大/变小的区域。透明度随场的强度最高约 0.50，近内沿略减，与 9 DIP 边缘折射衔接。落到当前岛洞的采样直接放弃。
- 捕获完成只保留这一帧垫边，不再与上一帧合并。边缘 `TryMap`、5 tap、无色散、圆角连续性和捕获排除域都不改。忙碌时仍各一个捕获/渲染任务，不增无限队列。

## 验证边界

- Core 增加光学弹簧、限幅、传送对齐、只采样实况垫边、洞内毒色不被取用、垫边更新立即反映，以及多 DPI 坐标测试。既有薄中心、中性预乘和零分配回归在强度为 0 时仍应成立。
- `tools/GlassProbe` 写出 `lag-before.ppm` / `lag-after.ppm`（同一挖洞实况源），并统计内部扭曲路径的合成耗时。本 box 一次 Linux Release 结果：仅边缘的 CPU 回退 534×230 平均约 2.668ms、p95 约 2.922ms，分配 0 字节；打开对当前挖洞捕获的内部位移扭曲后平均约 10.314ms、p95 约 11.590ms，分配 0 字节（未超过 16.67ms 的 CPU 回退预算，但仍优先走 GPU）。图和数字都是 Linux 上的算法验证，**不是真实 Windows 截图或 GPU FPS**。
- Windows CI 在原有挖洞对照之外，用挖洞后的实况垫边做滞后 WARP 软件设备对照，阈值仍是 4/255。这不是硬件 60fps。
- 正下方捕获的版本门槛、黑块回退和 Windows CI 合成叠层探针见 [正下方捕获](glass-underlay-capture.md)。尚未在用户真实 Windows 桌面证实露出的是底下内容而不是黑块。
