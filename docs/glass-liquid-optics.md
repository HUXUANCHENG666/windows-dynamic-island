# t59：玻璃内部的液态滞留折射

内部仍然通透，不铺模糊或近黑遮罩，也不把一整张旧截图贴在岛里。透过玻璃看到的背景在**世界坐标**里带阻尼滞后，拖动或展开时短暂滞留并缓慢流回，收敛后不再覆盖实况桌面。

## 根因

此前只有最多 9 DIP 的边缘从岛外垫边取色；`distance <= -band` 的内部直接写 0。分层窗口中间是真透明，所以拖动时透过的是 1:1 实景，没有液体惯性。已有浅水高度场只扰动边缘采样，不能单独填满内部：岛洞在捕获里被清掉，几个像素的法线偏移到不了垫边。

当前捕获仍必须挖掉岛身（BitBlt 会拍到岛自己）。因此内部不能假装“此刻正下方的桌面已在纹理里”。

## 做法

- `LiquidOptics`：对岛的屏幕位置和尺寸做近临界弹簧（k=81，c=17，ζ≈0.94）。窗口仍 1:1 跟手，Q 弹不变。采样原点/尺度滞后，单轴位移上限 48 DIP，尺寸滞后上限 56 DIP，都小于 72 DIP 垫边，避免拖出有效纹素后胡乱取样。跨屏或超过 240 DIP 的跳跃直接对齐，防止无限拖影。静止约 0.4 秒内收敛；偏移低于约 0.75px 时强度为 0，避免微抖。
- 内部采样：`u = pad + x·lagScaleX - lagX`（RGB 同位），再叠加有限的高度场斜率（`InteriorSlopeWarp=2.5`）。透明度随滞后幅度最高约 0.50，近内沿略减，与 9 DIP 边缘折射衔接。静止后内部不再画，动态壁纸/视频从真透明中心继续更新。
- `LiquidBackdrop`：按世界坐标合并历次**有效**垫边像素。岛移开或长大后，曾经露在外面的桌面可被滞后采样；当前岛洞里的自身像素不会写进缓存。从未见过的区域保持 0，渲染时透出实况，不编造颜色。
- GPU 与 CPU 共用同一套映射；边缘 `TryMap`、5 tap、无色散、圆角连续性和捕获排除域都不改。忙碌时仍各一个捕获/渲染任务，不增无限队列。

## 验证边界

- Core 增加光学弹簧、限幅、传送对齐、世界缓存合成、滞后边界取色和多 DPI 坐标测试。既有薄中心、中性预乘和零分配回归在强度为 0 时仍应成立。
- `tools/GlassProbe` 另外写出 `lag-before.ppm` / `lag-after.ppm`，并单独统计内部滞后路径的合成耗时。本 box 一次 Linux Release 结果：仅边缘的 CPU 回退 534×230 平均约 2.899ms、p95 约 3.200ms，分配 0 字节；打开内部滞后并填充历史像素后平均约 20.819ms、p95 约 21.970ms，分配 0 字节。这已超过 16.67ms 的 CPU 回退预算，因此内部滞留效果优先走 GPU；CPU 回退在拖动/展开期间可能会掉到预算以下。图和数字都是 Linux 上的算法验证，**不是真实 Windows 截图或 GPU FPS**。
- Windows CI 在原有挖洞/无滞后对照之外，增加有历史填充和滞后的 WARP 软件设备对照，阈值仍是 4/255。这不是硬件 60fps。
- 未在真实 Windows 桌面预览；未证实 BitBlt 去掉岛窗的可靠性，因此没有改捕获标志去“拍到正下方”。快速展开时，超过旧垫边范围、从未捕获过的新内部仍会透出实况。
