# 灵动岛开发文档

本文说明这个仓库在做什么、代码怎么组织、液态玻璃和实况捕获如何工作、怎样在本机和 CI 里构建测试，以及正式版与测试分支的关系。它面向后来接着改代码的人，可以单独阅读。更细的专题仍在同目录其它文里，文末有索引。

本文不代替用户手册。日常使用、托盘菜单和权限说明见仓库根目录的 `README.md`，安装包里的短说明是 `packaging/使用说明.txt`（打包装成 `readme.txt`）。

除非另有标明，文中的测试数字都来自 Linux 开发机上的单元测试，或 GitHub Actions 的 Windows runner 合成桌面。它们**不是**用户真实桌面的实测，也**不表示**用户机器能跑到 60fps。帧预算按 16.67ms 来设计，日志里的 `ui-submit/s` 是提交次数，不是显示 FPS。

## 1. 项目目标

灵动岛是一个 Windows 桌面程序：屏幕顶部正中停着一颗黑胶囊。有音乐时显示封面和波形；鼠标靠近时用弹簧展开成播放器。音量、电池、倒计时、通知也可以从这里冒出来。另外还做了：

- **液态玻璃**：在胶囊上对「此刻岛正下方」的桌面做水体一样的透镜和贴边折射，而不是系统自带的 Acrylic / Mica，也不改 `Window.Opacity`。
- **实时翻译**：可选把系统正在播放的音频转成字幕并译成中文，或翻译剪贴板。
- **不抢焦点**：窗口置顶，但使用不激活样式，不进任务栏和 Alt+Tab，点击可以穿过岛外的区域。黑色托盘图标提供设置和退出。

需要 Windows 10 版本 2004（build 19041）或 Windows 11。程序自带 .NET 运行库，用户不必另装。

## 3. 架构概览

解决方案是两个项目：

- **`src/DynamicIsland.Core`**：与 UI 无关的逻辑。几何、弹簧、光学、翻译策略、设置模型、通知和媒体策略都在这里。可在 Linux 上跑单元测试。
- **`src/DynamicIsland`**：WPF 壳。窗口、托盘、主题、Win32 捕获、D3D11 玻璃渲染、服务接线和设置界面。目标框架是 `net8.0-windows10.0.19041.0`，在非 Windows 上要用 `-p:EnableWindowsTargeting=true` 才能编译。

运行时大致分成几条互不阻塞的线：

1. **位置与形状。** 指针、投掷和展开弹簧每帧先更新窗口位置和胶囊尺寸。这条路径**不等待**屏幕捕获，也不等待 GPU 画完。跟手必须是 1:1，Q 弹也是。
2. **玻璃。** 在后台有一个捕获任务、一个渲染任务，完成槽只有一个。有可用垫边时，立刻按**当前**几何重采样，捕获在旁边更新。GPU 优先，失败则 CPU。输出写进可复用的 `WriteableBitmap`。
3. **翻译与其它服务。** 音频、字幕、翻译 HTTP、媒体控件、音量电池各自在自己的服务里跑，不插入玻璃的 16.67ms 预算。

窗口是分层、置顶、不激活的。胶囊填充是深色岛身（`Theme.IslandFill`）。玻璃是叠在岛身上面的一张图。因此：**中间一旦没有不透明的实况像素，用户看到的就是黑岛身**，不要把这种「其实是全透明」说成效果已经正确。

## 5. 液态玻璃和捕获管线

### 5.1 为什么不能直接截岛下面的图

普通 `BitBlt` 在现代 DWM 下，对分层置顶窗常常拷到的是窗口自己，而不是底下的桌面。也不能靠藏窗或改 `Window.Opacity` 去「让一下」再截，那会闪。系统的 Acrylic / Mica 以及 Composition 背景画刷通常只能显示，不能把像素读回给现在的五 tap 采样，本项目不用它们来冒充玻璃。

正式路径是：在 Windows 10 2004 / build 19041 及以上，对**灵动岛顶层窗口**设置 `SetWindowDisplayAffinity(WDA_EXCLUDEFROMCAPTURE)`（`0x11`）。这样捕获 API 会跳过本窗，露出底下那一层。更早的系统**不能**设这个标志：官方行为是静默变成 `WDA_MONITOR`，捕获里会是一块黑。设置窗和托盘不加这个标志；关闭玻璃或退出时恢复 `WDA_NONE`。

玻璃开着时，本岛可能不会出现在 Win+Shift+S、游戏栏等同样走这套捕获 API 的工具里。

### 5.2 Live、黑块、空洞

捕获结果要先分类，再决定能不能当内景，见 `GlassUnderlay`：

- **Live**：内部有足够的不透明像素，而且不是「垫边明显有颜色、内部却几乎纯黑」。
- **BlackHole**：垫边有彩，内部几乎全黑。常见于排除失败或 `WDA_MONITOR`。这样的帧**不能**当实况去画，否则中间会被涂成不透明黑。
- **Missing**：内部几乎没有不透明像素，包括裁切后只剩一角的情况。同样不能当整幅实况。

纯黑壁纸是两边都黑，必须判成 Live，不能当成黑块永远挖洞。分类时会忽略 alpha 很低的样本；若岛内部透明样本过多（覆盖率不足约 90%），直接判 Missing，避免不完整的桌面复制被当成 Live。

挖洞回退时，只把当前圆角岛挖成 0，边缘垫边仍可折射。这时中心是真透明，底下是黑岛身——这是回退，不是修好了的清水内景。

### 5.3 DDA 与 GDI

允许取正下方时，优先走 DXGI Desktop Duplication（DDA）：零超时取最新桌面，桌面没变不算失败，可复用上一张。捕获矩形稍微越出屏幕时，只裁切相交部分并保留会话，不要为此拆掉 DDA、冷却 10 秒再改走 GDI（那会让采样路径来回切）。

若 DDA 得到的是彩色 Live，直接用。若内部几乎全黑（既可能是真黑壁纸，也可能是 DDA 黑块），先打一张 GDI `BitBlt` 对比：GDI 的内部更有彩色实况，就改用 GDI；两边都黑，按真黑壁纸保留，不挖洞。DDA 失败或判定不是 Live 时，再走 GDI；仍不行则挖洞回退。

捕获在专用线程上进行，因为 `CreateDC("DISPLAY")` 的 DC 有线程亲和。同一时间只跑一个捕获任务，不用无界队列，也不在 UI 线程上阻塞等待。

### 5.4 透镜和 9 DIP 边带

用户在 t71 已肯定当时的外观，后来的修复尽量不动这些参数：

- 内部是清水透镜，中心大约 1.18 倍，平方穹顶，越靠近边缘收缩越快。
- 约 2 倍边带处开始渐隐，到内沿（1 倍边带）接上贴轮廓的 **9 DIP** 折射与高光。内部和边缘走两条路径，不要把透镜公式画进边带。
- RGB 同位五 tap，没有人为色散。
- 内部实况透明度大约 0.96，避免和合成器的真透明叠成双重影像。
- HLSL 里的 1.18 和混合起止必须与 C# 的 `WaterLens` 常量一致。

CPU 与 GPU 共用这套映射。GPU 用 D3D11，回读最多三个暂存缓冲、不阻塞等待；不行再走 CPU。有 Live 内景时，CPU 输出长边限制在 384，以免五 tap 打穿帧预算。

### 5.5 拖动、迟到帧、几何邮箱

快拖时不要因为位置对不上就把整幅玻璃关成全透明（那是 t69 的旧策略，t71 已改掉）。显示中的位图只在输出尺寸或缩放会明显拉伸时才撤下。旧垫边只要不超过约 350ms，就按**当前**几何重新取样，不要把旧位图拉伸到新尺寸。在静态桌面上，这样重采样与「到新位置再捕一张」在内部是对齐的。

异步光栅（尤其 GPU 会先交出上一拍回读）如果按旧的 Left/Top 画好再显示，中间的世界内容会往后倒再弹回来，看起来就是拖动时中间抽动。所以：已有显示帧时，只接受位置误差不大于当前已显示帧的新结果。更旧的迟到帧丢掉，但玻璃保持可见。

工人忙时只用容量为 1 的邮箱记住**最新**几何，空出来立刻按新位置画，不排队积压。位置和投掷仍然不等待这次绘制。

另外，没有实况内景的帧即使位置更近，也不能替换已经显示的活体内景，否则中间会再次变黑。反过来，已显示的是空内景、新帧有实况时，应当换上。

### 5.6 诊断

玻璃大约每 10 秒打一行诊断，不含屏幕内容：`capture/s`、`completed/s`、`ui-submit/s`、捕获/渲染/写回/帧龄的 p95，以及 DDA/GDI 计数和跳过原因。这些是 runner 或本机上的管线节拍，不是用户显示器的 FPS，也不要拿来宣传 60fps。

## 6. 实时翻译（摘要）

实时翻译把系统播放的音频做成字幕并译成中文。识别走本机 Whisper（CPU 或 Vulkan 运行库，随包装在 `runtimes/` 里）。翻译源由用户在设置里显式选择，例如 MyMemory、Azure、DeepL、LibreTranslate 自建或 OpenAI 兼容接口。程序不会为了「多个免费源」去广播同一段文字，也不会在冷却期自动换源。

额度、密钥和地区限制以各源官方说明为准，详见 `docs/translation-providers.md` 和 `docs/live-translation-reliability.md`。日志不写译文正文、请求 URI 或密钥。

## 7. 本机构建和测试

需要 .NET SDK 8（见 `global.json`，当前写的是 8.0.400，允许同一主版本内向前滚动）。在 Linux 上编译 WPF 项目时加上 `EnableWindowsTargeting=true`。

```bash
# 核心逻辑测试（Linux / Windows 都可以）
dotnet test tests/DynamicIsland.Core.Tests/DynamicIsland.Core.Tests.csproj -c Release

# 编译 WPF（在非 Windows 上必须开 Windows targeting）
dotnet build src/DynamicIsland/DynamicIsland.csproj -c Release -p:EnableWindowsTargeting=true -warnaserror

# 自包含 win-x64 发布（产物目录默认 artifacts/publish）
./build/publish.sh
```

Windows 上还可以跑工具项目（均不是用户桌面 FPS 证明）：

- `tools/GlassPerfCheck`：合成 CPU 渲染耗时
- `tools/GlassGpuCheck`：WARP 像素对照
- `tools/GlassPipelineCheck`：捕获-渲染-提交与快拖可见性
- `tools/GlassUnderlayCheck`：合成叠窗上的排除捕获
- `tools/SettingsUiCheck`：无头加载设置布局

设置 XAML 契约：`python3 build/check-settings-xaml.py`。着色器编译检查：Windows 上跑 `./build/check-glass-shader.ps1`。

改玻璃时至少要保证：Core 测试通过（含光学、分类、拖动连续性和活体内景）、WPF 能在 `warnaserror` 下编译。完整 WARP / 管线 / 捕获探针以 CI 的 Windows job 为准。

## 8. CI 如何打 Windows 试用包

工作流是 `.github/workflows/windows.yml`，在 push、pull_request 和手动触发时运行，名字是 **Build Windows package**。

1. **test**（`ubuntu-latest`）：设置 XAML 检查、Core 测试、CPU 合成耗时。
2. **package**（`windows-latest`）：再跑 Core 测试和 CPU 耗时，编译着色器，WARP 对照，无头设置布局，管线节拍，合成叠窗捕获探针，然后 `build/publish.sh` 发布自包含 exe，把 `packaging/使用说明.txt` 复制为 `readme.txt`，与 `DynamicIsland.exe`、`runtimes/` 一起打成 `DynamicIsland-win-x64.zip`，上传为构件 `DynamicIsland-win-x64`。
3. **release**：只在标签以 `v` 开头时运行（例如正式的 `v1.0.0`）。向 `feature/live-audio-translate` 推送**不会**走这一步，也就不会改正式 Release。

试用包的校验清单：压缩包里要有 `DynamicIsland.exe`、`runtimes/`（至少 `runtimes/win-x64/whisper.dll`，以及 Vulkan 目录若按脚本要求存在）、`readme.txt`。把整个压缩包解压后再运行，不要只拷走 exe。

## 9. 已知限制和设计决策

- **捕获在用户机器上是否露出正下方，只能在那台 Windows 上确认。** CI 的叠窗探针和开发箱上的单元测试都代替不了。失败时应回退到挖洞，而不是用黑像素把中间涂实。
- **不要宣称 60fps。** 预算是 16.67ms。CI 上常见的提交率大约每秒三十多次，捕获帧龄仍可能有几十毫秒，视路径和桌面负载而定。
- **快拖整幅变全透明**曾经用来避免拉伸旧帧，但用户会觉得效果「没了」。现在只在尺寸/缩放不匹配时撤下位图。
- **历史截图拼贴**不会再拿来填内部。要的是当前几何下的实况重采样。
- **暗色或纯黑壁纸**必须能保留为 Live。只有「垫边有彩、内部几乎全黑」才是捕获失败的黑块。
- 玻璃开启期间本窗可能从系统截图/录屏中消失，这是排除捕获的副作用。
- 翻译源的免费额度、地区和密钥由用户自己准备，程序不自动开通、不轮询多个源。
- 试用包没有代码签名，SmartScreen 会提示发行者未知，这是预期现象。
